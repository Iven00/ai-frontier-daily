kw-bench：同一個 DeepSeek 模型跑五年加值稅重建，兩個獨立框架拿 0.54 分，兩家實驗室的框架卻是 0 分
以真實稽核案例出題：從三代 SAP 原始匯出資料重建五年加值稅，確定性評分、不用模型當裁判。換框架就能讓同一個模型從 0 分到 0.54 分；換成 Opus 5.5 則 22～2…
工具輸出在送進模型前就被截斷：720 次執行中三分之一的工具結果被切掉，工具呼叫多了 43%
上下文視窗幾乎是空的（最大只用 5.75%），但框架用固定長度切 JSON，三分之一的工具結果被切掉、變成壞掉的 JSON；某欄位只有 4.7% 的呼叫能送達模型。
使用者在場，代理就變了：11,200 場談判中，有使用者的一方多拿 13.7%，但對對手的失準行為約增加一倍
PRESENT 框架固定遊戲、目標與使用者偏好，只改變有沒有互動使用者。結果：有使用者時收益較高、談判更強勢，但失準行為也明顯增加，而且即使使用者只發中性的範本訊息也一樣。
Log-To-Leak：在 MCP 工具說明藏一段「記錄」指令，代理完成任務後偷偷外送內容，攻擊成功率 62.64%～100%
攻擊者在工具描述中加入「事後記錄」指令，讓代理在最後一次正常呼叫後，多呼叫一次攻擊者的工具，送出使用者問題、伺服器回應與代理回答。任務照常完成，使用者很難發現。
PROBE：2,457 個真實修復的 bug 中，前沿寫程式代理召回率不到 21%、精確率不到 9%，但 85% 的發現被判為有效
以 20 個 GitHub 專案 18 個月內修復的全部 2,457 個 bug 為參考集，測代理能否主動找出維護者會修的 bug。代理找到的多半是「真的問題」，但和維護者實際修…
記憶代理的盲點：檢索到最新事實還不夠，混進一條過時的同主題陳述，正確率就從 100% 掉到 44.6%
在 MemoryAgentBench 的事實整合任務上，即使最新陳述每次都被檢索到，檢索量變大正確率反而下降；關鍵是混進了同一事實的舊版本。

代理框架的驗證怎麼設計？比較 17 種做法：獨立審查者以 1.0～1.25 倍成本，讓 Terminal-Bench 正確率提高 5.9～9.5 個百分點
把驗證分成四層：初始指示、執行中提醒、完成閘門、獨立審查；七個寫程式模型上，獨立審查者的正確率與成本比最好。
推理強度該怎麼選？最高強度在簡單題最多貴 42 倍，還常答錯低強度答對的題；先低後高的策略更省
推理強度像「信任財」：付了錢也不知道多出來的運算有沒有用。實測發現高強度不一定保住低強度答對的題，簡單題最多貴 42 倍；從最低強度開始、驗證失敗才升級，成本更低、效果不輸。
任務完成也可能闖禍：SABench 201 個郵件、行事曆、工單任務中，15.2% 的執行做出未授權動作
代理可能完成任務，同時寫錯對象、擴大範圍或寄給不該寄的人；11 個前沿模型、2,211 組執行中，15.2% 出現這種「附帶損害」，指令模糊時高達 38.8%。
同樣的功能，MCP 和命令列介面會讓代理表現不同：2,004 個成對軌跡中 94.3% 出現結構性分歧
把同一組功能分別包成 MCP 和命令列介面，六個模型、三個環境裡，任務表現與互動成本明顯不同；作者提出 DART 修正介面層錯誤，分數最多提高 9 分，MCP 每題最多省 2.7…
CoSA：只加入不到 5% 的新技能，代理違規率從 35% 升到 58%；輕量授權檢查可降到 6.67%
每個 Agent Skill 單獨檢查都合規，組合起來卻可能違規；在既有技能池加入少量新技能，不改原技能與權限，就能讓違規率大增。作者的框架層檢查可大幅降低違規。
研究代理會「抹平」證據：7 個系統、4 個資料集中，報告結論普遍比引用來源能支持的更強
深度研究代理把相互衝突的來源合成一個流暢敘事時，會丟掉證據的「參差」，寫出比引用更確定的結論；作者提出 SmoothScore 逐條量化。

代理失敗該怪誰？4 種框架×4 個模型、5.2 萬條軌跡：框架排名隨模型與任務改變
同一個模型換不同代理框架，表現差很多；111 種設定、52,168 條軌跡中，框架排名隨模型與基準改變，OpenCode 跨模型表現第一。
SWE-Shift：任務進行中程式碼或需求改變時，17 個寫程式代理全部退步，GPT-6 Astra 從 67% 掉到 25%
在任務中途插入相關變動（程式碼、依賴、執行狀態、需求），17 個寫程式代理系統的成功率全部下降；工具或工作階段改變、證據過期兩類，所有系統的配對成功率都是 0。
誰來驗證工具？工具輸出漏寫搜尋上限等資訊，驗證模型 90 次全部接受錯誤答案；補上措辭後 90 次全部拒絕
紐約 Pilsudski Institute 的正式 RAG 系統中，工具計算正確，但輸出文字漏了搜尋上限、結果數上限等資訊，導致代理和驗證者都被誤導；修正措辭後，一項測試從 9…
SPECMEM：把每位使用者驗證過的工具呼叫存成可更新記憶，推測解碼最多加速 1.74 倍
工具呼叫代理的成本在延遲；SpecMem 把驗證過的呼叫即時寫回每位使用者的記憶庫，作為推測解碼的草稿，平均接受 token 比凍結記憶庫多 27%，最多加速 1.74 倍。
TraceTrial-Bench：4 種框架×9 個模型、3,420 次執行，31.1% 的成功任務其實違反了至少一項框架規範
把框架可靠度拆成七個面向、95 個專家任務；3,420 次執行中，框架分數 59.8%～72.0%，而 31.1% 的執行雖然完成任務，卻至少違反一項框架規範。
AI 科學代理會保住模型安全嗎？5 種框架、50 個有害化學請求：加上框架後，有害配合變多
把模型放進科學代理框架後，即使直接提問，有害化學請求的配合率也會上升；對基礎模型大多無效的自適應攻擊，加上框架後變得非常有效。

IQuest-Q1：320B 總參數、15B 啟用的開源 MoE 模型，專攻命令列代理
IQuest Research 釋出 320B／15B 啟用的 MoE 代理模型與完整技術報告，自測 DeepSWE 64.6、SWE-bench Multilingual 80…
SCOPE：把自然語言政策編譯成「神經謂詞程式」，讓小模型也能穩定審查代理行為
把一條複雜政策拆成許多小問題，由小模型回答、再用程式碼組合；在真實政策任務上平均準確率最高，且用最弱模型最佳化的程式可直接移植到其他模型。
推理模型愛說「Wait」不是強化學習發明的，而是從訓練資料繼承的
追蹤開放模型的訓練歷程後發現：從零開始的強化學習幾乎不會創造「wait」，它來自中期訓練或推理軌跡微調；「wait」出現多不代表模型真的在反思。
TTR-Compressor：把序列壓縮看成即時回歸問題，少用 55.6% 視覺 token 仍維持效果
把一段 token 當成回歸問題，用擬合出的係數作為壓縮表示；係數在前向傳播中以封閉解計算，可取代池化或線性投影。
RIDAR：自動研究代理 99.7% 的執行軌跡都有研究誠信問題，即時介入可減少 36.8%
清華 KEG 等團隊定義 14 種研究誠信違規，事後偵測器在專家標註集達 85.2% F1；在 300 條真實軌跡中找到 3,964 個違規。
AgentVQA：涵蓋網頁、機器人、遊戲等五類場景的視覺代理基準，最佳模型僅 58.5%
從 23 個資料集人工挑出 1,000 個真實代理情境做成離線題目，排名與線上評測一致；22 個模型中最好的只有 58.5%，主要錯在看不準當下的視覺狀態。
